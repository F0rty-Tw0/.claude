# User Notes

- **Config locations**: MCP servers in `~/.claude.json`; hooks wired in `~/.claude/settings.json`, scripts in `~/.claude/hooks/`.

# Agents

Local agents live in `~/.claude/agents/` — invoke by bare name (`executor`, `architect`, …). The roster and descriptions are injected every session; don't duplicate the list here.

- **Delegate sizeable code work.** Send source-code changes that are large, or that split into independent parallel tracks, to `executor` / `deep-executor`. Make small edits (a handful of tool calls) yourself — a subagent re-reads context and costs more than the edit. Edit config/orchestration files (`~/.claude/**`, `CLAUDE.md`) directly.
- **Model is per-agent.** `sonnet` + `effort: high` for routine tool-checked work (git-master, writer — trial since 2026-10-05), `opus` for judgment-heavy specialist work, `inherit` for implementation (executor, debugger, test-engineer), verification, and high-risk analysis/review. Model doesn't set reasoning effort; the `effort:` frontmatter field does. Frontmatter is the default only: a plan task's **Model** line overrides `model` and `effort` on that call (tiers in skill:plan `references/task-format.md`: start at sonnet, opus on evidence). Off-plan, override on the call for an exceptionally hard task instead of changing the agent's default.
- **Agent lifecycle.** `TaskStop` an agent that is still running or idle once its report is used; one whose status is `completed` needs nothing (106 failed stops in two weeks). A subagent's cache lives 5 minutes, so a follow-up to one idle longer goes to a fresh agent with a short brief, not `SendMessage`. Spawn agents without `name`: a named agent becomes a teammate, and each finish wakes you with an `idle_notification` that repeats its whole report (thousands a month). `SendMessage` reaches an unnamed agent by id. Name one only when the user asks for a team.
- **Long reports.** A reply ending in a scratchpad path (`…/reports/<agent>-<slug>.md`) is complete: act on its verdict and summary, and `Read` the file only for detail. Put the resolved scratchpad directory in the brief; a subagent may not see it.
- **Worktree briefs.** A brief for an `isolation: "worktree"` agent says `Your cwd is the worktree; use paths relative to it.` and carries no absolute path into the main checkout (no `Repo:` line). `.claude/local/plans/**` is gitignored and absent in a worktree: paste what the agent needs.
- **Time budget.** Every brief states `Expected: N min` (default 15 for executor, 30 for deep-executor, 20 for a reviewer). Dispatch in the background and note the start time. The clock restarts at each new assignment (a dispatch or a `SendMessage` with new work); a brief that covers several slices states N per slice, and idle time between assignments doesn't count. At 2× of the current assignment with no report, `TaskStop` the agent, read its partial diff or report file, then take over or re-dispatch the unfinished part smaller. Nothing else stops a runaway: the retro found runs of 640 minutes.
- **Timing runs** over ~10 min go to a fresh bench agent, not the executor that built the change.
- **CPU-heavy runs** are wrapped in the shared lock by `hooks/cpu-guard.js` in every repo on a machine with `flock` (opt out with a `.claude/cpu-guard.off` file); it puts rtk's form inside the lock only when `rtk` is on PATH. Write the wrap yourself, so the hook has nothing to rewrite (a rewrite in auto mode costs a repeated call): `~/.claude/scripts/cpu-lock bench <cmd>` (exclusive) for benches and timing, `cpu-lock gate <cmd>` (shared) for full gates and e2e. The lock needs `flock`: Linux has it; macOS `brew install flock` once per machine; without it (stock macOS, Git Bash) `cpu-lock` runs the command unlocked and says so, so agree bench times with the other sessions by message. `cpu-lock` is a bash script: call it from the Bash tool, not PowerShell. On Windows, and on a machine without `flock`, `cpu-guard.js` does nothing.
- **Tie-breaks:** `executor` by default, including plan tasks that name their files and a test, however many systems they cross. `deep-executor` only when requirements are unclear or `executor` returned BLOCKED; it costs about 2x an Opus executor run. `test-engineer` for coverage-gap audits and flaky-suite hardening, not per feature. `/plan` writes the plan, `architect` reviews design, `critic` attacks the spec and the plan. `code-reviewer` checks a whole step against the plan; `security-` / `performance-` / `quality-reviewer` are single-dimension deep passes.
- **Recipes, when the user asks for a full pipeline** (≤3 agents in parallel):
  - Feature: `brainstorming` → `/plan` → `executor` (ships its own tests) → `quality-reviewer`; run the final build/tests yourself.
  - Bug: built-in `Explore` → `debugger` → `executor` (adds the fails-on-revert test).
  - Review panel: `quality-reviewer` + `security-reviewer`, plus `performance-reviewer` only when the diff touches a hot path, a bench or a budget test, or the plan marks the task performance-sensitive (about 70% of its first passes found nothing, 1–15 Nov 2026).

# Terminal output

Bash output arrives raw: the hook that rewrote every command through `rtk` was removed on 2026-11-15. In auto mode a hook rewrite voids the permission review, and each one cost a repeated call (about 1,000 in two weeks). For noisy runs (eslint, Playwright, long test logs) write `rtk <cmd>` yourself; cpu-guard still adds it inside its lock. Without rtk on PATH (the usual cloud case) `scripts/cloud-setup.sh` drops cpu-guard: run commands plainly.

Quote a pattern meant for the tool, not the shell (`--include='*.ts'`): zsh aborts the whole command on an unmatched pattern (377 times in two weeks).

Line endings: check with `git ls-files --eol <file>` (or, in the Bash tool, `tr -cd '\r' < f | wc -c`), never `grep -c $'\r$'`, which counted every line as CRLF in Git Bash here.

# Disk hygiene

On 2026-11-15 build output and scratch dirs had grown to ~310 GB: one worktree's `target` at 152 GB, `~/.cache/cqt-ci` at 83 GB, and 525 `~/.cache/tc-*` / `rv-*` dirs.

- Scratch dirs you create outside the session scratchpad: create them under the OS temp dir or `~/.cache/<prefix>-*` (macOS `~/Library/Caches`, Windows `%LOCALAPPDATA%\Temp`) and append each absolute path to `~/.claude/state/owned-<session id>.txt` (`$CLAUDE_CODE_SESSION_ID` in Bash, `$env:CLAUDE_CODE_SESSION_ID` in PowerShell). `hooks/delete-guard.js` then lets `rm -rf <literal absolute path>` (PowerShell: `Remove-Item -Recurse -Force <path>`; on Windows only the PowerShell form) through without a permission prompt, for them and for anything inside your scratchpad; any other spelling goes through the normal check. Delete them before your final report, without asking; keep one only when a later step needs it, and say so in the report.
- Your own clean worktrees: `git worktree remove <path>` (never `--force`) without asking the user. It also deletes gitignored files in the worktree, so look for a `.env` or other untracked config first.
- Temp dir full or over quota: delete your own scratch first, point `TMPDIR` at a new `~/.cache/<prefix>-tmp` (append it to the owned list), and message the session that owns the rest (`ListAgents`, `SendMessage`). Do not wait for the user and do not delete another session's files.
- Cargo build output lives under `~/.cache/cargo-build` (dev builds, one dir per workspace and checkout) and `~/.cache/cqt-ci/<worktree>` (cqt-monitor local CI). `~/.claude/scripts/build-prune` cuts both back to 120 GB in total whenever the machine is idle; a systemd user timer tries every 10 minutes. So do not delete a passing run's cache. A prune can remove a CI dir together with its `release/cqt-studio`: copy a binary aside when a later step needs it. `build-prune --dry-run` shows what the next run would delete.
- Retiring a worktree: run `cargo clean --manifest-path <manifest>` for each of its workspaces, then `git worktree remove`. `cargo clean` removes the build dir and the whole in-tree `target`, which can also hold evaluation data (`target/radio`, `target/scale`): move what you need first.
- Before deleting build output or a shared cache, check that no `cargo` or `rustc` is running (Linux, macOS: `pgrep -x cargo; pgrep -x rustc`; Git Bash: `tasklist //FI "IMAGENAME eq cargo.exe"`, since its `ps` hides native processes; PowerShell: `Get-Process cargo,rustc -ErrorAction SilentlyContinue`) and ask the session that owns it (`ListAgents`).
