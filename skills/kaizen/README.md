# Kaizen

Continuous improvement principles applied to all code work. Small improvements continuously, error-proof by design, follow what works, build only what's needed.

## What It Does

Guides implementation, refactoring, and architecture decisions through four pillars:

| Pillar                         | Core Question                          | Red Flag                       |
| ------------------------------ | -------------------------------------- | ------------------------------ |
| **Continuous Improvement**     | Can I make this better while I'm here? | "I'll refactor it later"       |
| **Poka-Yoke (Error Proofing)** | How can I make this error impossible?  | "Users should just be careful" |
| **Standardized Work**          | What pattern does the codebase use?    | "I prefer to do it my way"    |
| **Just-In-Time (JIT)**         | Is this needed now?                    | "We might need this someday"  |

Each pillar includes concrete patterns: boy scout rule, type-system error prevention, codebase pattern matching, and YAGNI enforcement.

---

## When to Use

Triggers when you:

- Implement features or refactor code
- Review changes or make architecture decisions
- Address technical debt, code smells, or over-engineering
- Encounter YAGNI violations or premature abstractions

---

## Philosophy

**Kaizen is:** Small improvements continuously, preventing errors by design, following proven patterns, building only what's needed.

**Not:** Perfection on first try, massive refactoring, clever abstractions, premature optimization.

**Mindset:** Good enough today, better tomorrow. Repeat.
