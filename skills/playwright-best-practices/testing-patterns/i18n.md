Locale-dependent text is never asserted through `getByText` in a spec. Page objects locate by test id or role and expose `expect*` methods that take the expected string, so the same spec runs under every locale project. Every sample in this file lives under `e2e/i18n/`.

## Locale Configuration

### Setting Browser Locale

`locale` and `timezoneId` are context options, so one project per locale runs the whole suite under that locale. Each project's `use` is a named const. An RTL project (`ar-SA`, `he-IL`) needs only `locale`; the app sets direction from it. `snapshotPathTemplate` with `{projectName}` gives each locale project its own baseline folder, so one spec produces `en-US/homepage.png`, `de-DE/homepage.png`, and so on.

```ts
// e2e/playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

const chrome = devices['Desktop Chrome'];

const snapshotPathTemplate = '{testDir}/__snapshots__/{projectName}/{testFilePath}/{arg}{ext}';

const english = { ...chrome, locale: 'en-US', timezoneId: 'America/New_York' };

const german = { ...chrome, locale: 'de-DE', timezoneId: 'Europe/Berlin' };

const japanese = { ...chrome, locale: 'ja-JP', timezoneId: 'Asia/Tokyo' };

const arabic = { ...chrome, locale: 'ar-SA', timezoneId: 'Asia/Riyadh' };

const projects = [
  { name: 'en-US', use: english },
  { name: 'de-DE', use: german },
  { name: 'ja-JP', use: japanese },
  { name: 'ar-SA', use: arabic }
];

export default defineConfig({ projects, snapshotPathTemplate });
```

### Per-Test Locale Override

`test.use` inside a `GIVEN` overrides the project locale for that branch of the tree. The page object locates the button by test id and asserts the translated label it is given. Server-side locale detection reads the `Accept-Language` header, which is a context option too; the headers object is a named const because it is nested inside `test.use`.

| Override | `test.use` argument | Assertion |
|---|---|---|
| Browser locale and timezone | `{ locale: 'fr-FR', timezoneId: 'Europe/Paris' }` | `loginPage.expectSignInLabel('Connexion')` |
| `Accept-Language` header | `{ extraHTTPHeaders: SPANISH_HEADERS, locale: 'es-ES' }` with `SPANISH_HEADERS = { 'Accept-Language': 'es-ES,es;q=0.9,en;q=0.8' }` | `homePage.document.expectLang('es')` |

```ts
// e2e/i18n/pages/login.page.ts
import type { Locator, Page } from '@playwright/test';
import { expect, test } from '@playwright/test';

export class LoginPage {
  public readonly greeting: Locator;
  public readonly signInButton: Locator;

  private readonly page: Page;

  public constructor(page: Page) {
    this.page = page;
    this.greeting = page.getByTestId('greeting');
    this.signInButton = page.getByTestId('sign-in');
  }

  public async goto(): Promise<void> {
    await this.page.goto('/login');
  }

  public async expectGreeting(text: string): Promise<void> {
    await test.step(`THEN greeting reads "${text}"`, (): Promise<void> => expect(this.greeting).toHaveText(text), { box: true });
  }

  public async expectSignInLabel(label: string): Promise<void> {
    await test.step(`THEN sign-in button reads "${label}"`, (): Promise<void> => expect(this.signInButton).toHaveText(label), { box: true });
  }
}
```

The `lang` and `dir` attributes belong to the `html` element on every page, so a component object scoped to that locator owns them; `HomePage` exposes it as `document`.

```ts
// e2e/i18n/components/document-locale.component.ts
import type { Locator } from '@playwright/test';
import { expect, test } from '@playwright/test';

export class DocumentLocale {
  public readonly html: Locator;

  public constructor(html: Locator) {
    this.html = html;
  }

  public async direction(): Promise<string> {
    return this.html.evaluate((html: HTMLElement): string => window.getComputedStyle(html.ownerDocument.body).direction);
  }

  public async expectDir(dir: string): Promise<void> {
    await test.step(`THEN document dir is ${dir}`, (): Promise<void> => expect(this.html).toHaveAttribute('dir', dir), { box: true });
  }

  public async expectLang(lang: string): Promise<void> {
    await test.step(`THEN document lang is ${lang}`, (): Promise<void> => expect(this.html).toHaveAttribute('lang', lang), { box: true });
  }
}
```

## Testing Multiple Locales

### Parameterized Locale Tests

One case runs under several locales by looping over a typed list and giving each iteration its own `GIVEN` with `test.use`. The locale goes in the test title so the full path stays unique.

```ts
// e2e/i18n/common/i18n.type.ts
export type LocaleCase = {
  readonly button: string;
  readonly greeting: string;
  readonly locale: string;
};

export type LocaleExpectation = {
  readonly expected: string;
  readonly locale: string;
};
```

```ts
// e2e/i18n/login-locales.e2e.ts
import type { LocaleCase } from './common/i18n.type';
import { test } from './i18n.fixture';

const LOCALE_CASES: LocaleCase[] = [
  { button: 'Sign In', greeting: 'Hello', locale: 'en-US' },
  { button: 'Anmelden', greeting: 'Hallo', locale: 'de-DE' },
  { button: 'Se connecter', greeting: 'Bonjour', locale: 'fr-FR' },
  { button: 'ログイン', greeting: 'こんにちは', locale: 'ja-JP' }
];

test.describe('FEATURE: login page translations', () => {
  for (const { button, greeting, locale } of LOCALE_CASES) {
    test.describe('GIVEN a browser locale', () => {
      test.use({ locale });

      test(`SCENARIO: the login page in ${locale} translates the greeting and button`, async ({ loginPage }): Promise<void> => {
        await test.step('WHEN the login page is opened', (): Promise<void> => loginPage.goto());

        await test.step(`THEN the greeting reads ${greeting}`, (): Promise<void> => loginPage.expectGreeting(greeting));

        await test.step(`AND the sign-in button reads ${button}`, (): Promise<void> => loginPage.expectSignInLabel(button));
      });
    });
  }
});
```

### Locale Fixture

A test that compares two locales side by side needs two contexts. The fixture is a function that opens a context with the given locale, navigates, and returns a page object; every context it opened closes after the test. `PricingPage` (`e2e/i18n/pages/pricing.page.ts`) has `price = page.getByTestId('price')`, `goto()` to `/pricing`, and `expectPriceContains(text)` with `toContainText`. `EventPage` (`pages/event.page.ts`) has `eventDate = page.getByTestId('event-date')`, `goto(date: Date)` to `` `/event?date=${date.toISOString()}` ``, and `expectDate(text)` with `toContainText`.

```ts
// e2e/i18n/i18n.fixture.ts
import type { Page } from '@playwright/test';
import { test as base } from '@playwright/test';

import { CheckoutPage } from './pages/checkout.page';
import { EventPage } from './pages/event.page';
import { HomePage } from './pages/home.page';
import { LoginPage } from './pages/login.page';
import { PricingPage } from './pages/pricing.page';
import { ProfilePage } from './pages/profile.page';

type PricingIn = (locale: string) => Promise<PricingPage>;

type I18nFixtures = {
  readonly checkoutPage: CheckoutPage;
  readonly eventPage: EventPage;
  readonly homePage: HomePage;
  readonly loginPage: LoginPage;
  readonly pricingIn: PricingIn;
  readonly profilePage: ProfilePage;
};

export const test = base.extend<I18nFixtures>({
  checkoutPage: async ({ page }, use): Promise<void> => {
    await use(new CheckoutPage(page));
  },
  eventPage: async ({ page }, use): Promise<void> => {
    await use(new EventPage(page));
  },
  homePage: async ({ page }, use): Promise<void> => {
    await use(new HomePage(page));
  },
  loginPage: async ({ page }, use): Promise<void> => {
    await use(new LoginPage(page));
  },
  pricingIn: async ({ browser }, use): Promise<void> => {
    const pages: Page[] = [];
    const pricingIn: PricingIn = async (locale: string): Promise<PricingPage> => {
      const context = await browser.newContext({ locale });
      const page = await context.newPage();
      const pricingPage = new PricingPage(page);

      pages.push(page);
      await pricingPage.goto();

      return pricingPage;
    };

    await use(pricingIn);

    for (const page of pages) {
      await page.context().close();
    }
  },
  profilePage: async ({ page }, use): Promise<void> => {
    await use(new ProfilePage(page));
  }
});

export { expect } from '@playwright/test';
```

```ts
// e2e/i18n/pricing-locales.e2e.ts
import { test } from './i18n.fixture';
import type { PricingPage } from './pages/pricing.page';

test.describe('FEATURE: pricing page currency', () => {
  test('SCENARIO: pricing in en-US and de-DE shows each currency symbol', async ({ pricingIn }): Promise<void> => {
    const enPricing = await test.step('WHEN pricing is opened in en-US', (): Promise<PricingPage> => pricingIn('en-US'));

    const dePricing = await test.step('AND pricing is opened in de-DE', (): Promise<PricingPage> => pricingIn('de-DE'));

    await test.step('THEN the en-US price shows a dollar sign', (): Promise<void> => enPricing.expectPriceContains('$'));

    await test.step('AND the de-DE price shows a euro sign', (): Promise<void> => dePricing.expectPriceContains('€'));
  });
});
```

### Testing Locale Switching

`HomePage` owns the heading, the language menu, and two component objects: `document` for `lang` and `dir`, `translations` for the audits in [Translation Verification](#translation-verification). `switchLanguage` locates the menu item by its visible name because that name is the input of the test, not a locale-dependent assertion. `waitForFonts` is used in [Font Loading for i18n](#font-loading-for-i18n).

```ts
// e2e/i18n/pages/home.page.ts
import type { Locator, Page } from '@playwright/test';
import { expect, test } from '@playwright/test';

import { DocumentLocale } from '../components/document-locale.component';
import { TranslationAudit } from '../components/translation-audit.component';

export class HomePage {
  public readonly document: DocumentLocale;
  public readonly heading: Locator;
  public readonly languageButton: Locator;
  public readonly translations: TranslationAudit;

  private readonly page: Page;

  public constructor(page: Page) {
    this.page = page;
    this.document = new DocumentLocale(page.locator('html'));
    this.heading = page.getByRole('heading', { level: 1 });
    this.languageButton = page.getByRole('button', { name: 'Language' });
    this.translations = new TranslationAudit(page.locator('body'));
  }

  public async goto(): Promise<void> {
    await this.page.goto('/');
  }

  public async reload(): Promise<void> {
    await this.page.reload();
  }

  public async switchLanguage(name: string): Promise<void> {
    await this.languageButton.click();
    await this.page.getByRole('menuitem', { name }).click();
  }

  public async waitForFonts(family: string): Promise<void> {
    await this.page.evaluate((): Promise<FontFaceSet> => document.fonts.ready);
    await this.page.waitForFunction((name: string): boolean => document.fonts.check(`16px '${name}'`), family);
  }

  public async expectHeading(pattern: RegExp): Promise<void> {
    await test.step(`THEN heading matches ${pattern}`, (): Promise<void> => expect(this.heading).toContainText(pattern), { box: true });
  }
}
```

```ts
// e2e/i18n/language-switch.e2e.ts
import { test } from './i18n.fixture';

test.describe('FEATURE: language switching', () => {
  test.describe('GIVEN the home page in the browser locale', () => {
    test.beforeEach(async ({ homePage }): Promise<void> => {
      await test.step('GIVEN the home page is open', (): Promise<void> => homePage.goto());

      await test.step('AND the document lang is en', (): Promise<void> => homePage.document.expectLang('en'));
    });

    test('SCENARIO: choosing Deutsch renders the page in German', async ({ homePage }): Promise<void> => {
      await test.step('WHEN Deutsch is chosen from the language menu', (): Promise<void> => homePage.switchLanguage('Deutsch'));

      await test.step('THEN the document lang is de', (): Promise<void> => homePage.document.expectLang('de'));

      await test.step('AND the heading greets in German', (): Promise<void> => homePage.expectHeading(/Willkommen/));
    });

    test('SCENARIO: the chosen language survives a reload', async ({ homePage }): Promise<void> => {
      await test.step('WHEN Deutsch is chosen from the language menu', (): Promise<void> => homePage.switchLanguage('Deutsch'));

      await test.step('AND the page is reloaded', (): Promise<void> => homePage.reload());

      await test.step('THEN the document lang is still de', (): Promise<void> => homePage.document.expectLang('de'));
    });
  });
});
```

## RTL Layout Testing

### Verifying RTL Direction

Two checks cover direction: the `dir` attribute on `html`, and the computed `direction` of `body`, which catches a stylesheet that overrides the attribute. Both are `DocumentLocale` methods; `direction` reads the computed style through a typed `evaluate`.

```ts
// e2e/i18n/rtl-direction.e2e.ts
import { expect, test } from './i18n.fixture';

test.describe('FEATURE: RTL layout', () => {
  test.describe('GIVEN an RTL locale project', () => {
    test('SCENARIO: the home page document direction is rtl', async ({ homePage }): Promise<void> => {
      await test.step('WHEN the home page is opened', (): Promise<void> => homePage.goto());

      const direction = await test.step('AND the computed body direction is read', (): Promise<string> => homePage.document.direction());

      await test.step('THEN the html dir attribute is rtl', (): Promise<void> => homePage.document.expectDir('rtl'));

      await test.step('AND the computed direction is rtl', (): void => expect(direction).toBe('rtl'));
    });
  });
});
```

### RTL-Specific Element Positioning

`boundingBox()` returns `null` for a detached element. A shared util turns that into a thrown error so page objects compare plain numbers without a non-null assertion. A `DashboardPage.expectSidebarRightOfMain()` reads `boxOf(this.sidebar)` and `boxOf(this.mainContent)` and asserts `sidebarBox.x > mainBox.x` in a boxed step; the spec calls it in one `THEN`.

```ts
// e2e/utils/bounding-box.util.ts
import type { Locator } from '@playwright/test';

export type BoundingBox = {
  readonly height: number;
  readonly width: number;
  readonly x: number;
  readonly y: number;
};

export const boxOf = async (locator: Locator): Promise<BoundingBox> => {
  const box = await locator.boundingBox();

  if (!box) throw new Error('element has no bounding box');

  return box;
};
```

### Testing Bidirectional Text

Mixed Arabic and Latin content is asserted as text, then as width, so a collapsed or wrapped field fails even when its text is intact. `ProfilePage.expectFullNameWiderThan` reads the box through `boxOf`.

```ts
// e2e/i18n/pages/profile.page.ts
import type { Locator, Page } from '@playwright/test';
import { expect, test } from '@playwright/test';

import { boxOf } from '../../utils/bounding-box.util';

export class ProfilePage {
  public readonly fullName: Locator;

  private readonly page: Page;

  public constructor(page: Page) {
    this.page = page;
    this.fullName = page.getByTestId('full-name');
  }

  public async goto(): Promise<void> {
    await this.page.goto('/profile');
  }

  public async expectFullName(text: string): Promise<void> {
    await test.step(`THEN full name contains "${text}"`, (): Promise<void> => expect(this.fullName).toContainText(text), { box: true });
  }

  public async expectFullNameWiderThan(width: number): Promise<void> {
    const box = await boxOf(this.fullName);

    await test.step(`THEN full name is wider than ${width}px`, (): void => expect(box.width).toBeGreaterThan(width), { box: true });
  }
}
```

```ts
// e2e/i18n/bidi-text.e2e.ts
import { test } from './i18n.fixture';

test.describe('FEATURE: bidirectional text', () => {
  test('SCENARIO: an Arabic name with a Latin email renders on one line', async ({ profilePage }): Promise<void> => {
    await test.step('WHEN the profile is opened', (): Promise<void> => profilePage.goto());

    await test.step('THEN the full name shows the mixed text', (): Promise<void> => profilePage.expectFullName('محمد (mohammed@example.com)'));

    await test.step('AND the full name is not collapsed', (): Promise<void> => profilePage.expectFullNameWiderThan(100));
  });
});
```

## Date, Time & Number Formats

### Testing Date Formats

Format cases are `LocaleExpectation` values looped into one `GIVEN` per locale. `EventPage.goto` takes the date and builds the query string; `expectDate` asserts the rendered text.

```ts
// e2e/i18n/event-date.e2e.ts
import type { LocaleExpectation } from './common/i18n.type';
import { test } from './i18n.fixture';

const EVENT_DATE = new Date('2024-03-15');

const DATE_CASES: LocaleExpectation[] = [
  { expected: 'March 15, 2024', locale: 'en-US' },
  { expected: '15 March 2024', locale: 'en-GB' },
  { expected: '15. März 2024', locale: 'de-DE' },
  { expected: '2024年3月15日', locale: 'ja-JP' }
];

test.describe('FEATURE: event date formatting', () => {
  for (const { expected, locale } of DATE_CASES) {
    test.describe('GIVEN a browser locale', () => {
      test.use({ locale });

      test(`SCENARIO: the event in ${locale} reads ${expected}`, async ({ eventPage }): Promise<void> => {
        await test.step('WHEN the event page is opened', (): Promise<void> => eventPage.goto(EVENT_DATE));

        await test.step(`THEN the event date reads ${expected}`, (): Promise<void> => eventPage.expectDate(expected));
      });
    });
  }
});
```

### Testing Currency Formats

The case type gains a `currency` member. `ProductPage.goto(99.99, currency)` opens `/product?price=99.99&currency=<code>`; `expectPrice` uses `toContainText`. JPY has no decimals, so 99.99 rounds to `￥100`.

| `de-DE` | `EUR` | `99,99 €` |
| `ja-JP` | `JPY` | `￥100` |
| `en-GB` | `GBP` | `£99.99` |

## Translation Verification

### Checking for Missing Translations

Untranslated strings leak in a few recognisable shapes. One regex covers them and the failure message prints the body text that matched.

| Pattern | Leak |
|---|---|
| `\{\{.*\}\}` | Handlebars placeholder |
| `\$\{.*\}` | Template literal placeholder |
| `t\(["'][\w.]+["']\)` | i18n key exposed as code |
| `MISSING_TRANSLATION` | Library placeholder |
| `\[UNTRANSLATED\]` | Library placeholder |

The audit is a component object scoped to `body`, so any page can expose it as a field. Long translations overflow buttons and headings: `overflowingElements` compares `scrollWidth` to `clientWidth` in the browser and returns the offenders as `TAG: "text"` strings, so a failure names the element.

```ts
// e2e/i18n/components/translation-audit.component.ts
import type { Locator } from '@playwright/test';
import { expect, test } from '@playwright/test';

const MISSING_TRANSLATION = /\{\{.*\}\}|\$\{.*\}|t\(["'][\w.]+["']\)|MISSING_TRANSLATION|\[UNTRANSLATED\]/;

export class TranslationAudit {
  public readonly body: Locator;

  public constructor(body: Locator) {
    this.body = body;
  }

  public async overflowingElements(): Promise<string[]> {
    return this.body.evaluate((): string[] => {
      const elements = Array.from(document.querySelectorAll<HTMLElement>('button, .label, h1, h2, h3'));
      const overflowing = elements.filter((element: HTMLElement): boolean => element.scrollWidth > element.clientWidth);

      return overflowing.map((element: HTMLElement): string => `${element.tagName}: "${element.textContent?.substring(0, 20)}"`);
    });
  }

  public async expectNoMissingTranslations(): Promise<void> {
    const text = await this.body.textContent();

    await test.step('THEN body text has no untranslated markers', (): void => expect(text).not.toMatch(MISSING_TRANSLATION), { box: true });
  }

  public async expectNoOverflow(): Promise<void> {
    const overflowing = await this.overflowingElements();

    await test.step('THEN no text overflows its container', (): void => expect(overflowing).toEqual([]), { box: true });
  }
}
```

### Detecting Text Overflow

One `GIVEN` per locale keeps each locale's report separate; both audits run under it.

```ts
// e2e/i18n/translation-audit.e2e.ts
import { test } from './i18n.fixture';

const LOCALES = ['en-US', 'de-DE', 'fr-FR', 'es-ES'];

test.describe('FEATURE: translation completeness', () => {
  for (const locale of LOCALES) {
    test.describe('GIVEN a browser locale', () => {
      test.use({ locale });

      test.beforeEach(async ({ homePage }): Promise<void> => {
        await test.step('GIVEN the home page is open', (): Promise<void> => homePage.goto());
      });

      test(`SCENARIO: the home page in ${locale} shows no untranslated marker`, async ({ homePage }): Promise<void> => {
        await test.step('THEN the body has no untranslated markers', (): Promise<void> => homePage.translations.expectNoMissingTranslations());
      });

      test(`SCENARIO: the home page in ${locale} has no text overflowing its container`, async ({ homePage }): Promise<void> => {
        await test.step('THEN no element overflows', (): Promise<void> => homePage.translations.expectNoOverflow());
      });
    });
  }
});
```

## Visual Regression for i18n

### Locale-Specific Snapshots

With the `snapshotPathTemplate` from [Setting Browser Locale](#setting-browser-locale), one spec calling `expect(page).toHaveScreenshot('homepage.png')` after `homePage.goto()` writes a baseline per locale project.

### Critical Element Screenshots

Element snapshots catch overflow and truncation in the widgets that translations stress most, and stay stable when the rest of the page changes. `CheckoutPage.ctaButton` is located by a multi-language name pattern so the same locator works in every project.

```ts
// e2e/i18n/pages/checkout.page.ts
import type { Locator, Page } from '@playwright/test';

export class CheckoutPage {
  public readonly ctaButton: Locator;

  private readonly page: Page;

  public constructor(page: Page) {
    this.page = page;
    this.ctaButton = page.getByRole('button', { name: /checkout|kaufen|acheter/i });
  }

  public async goto(): Promise<void> {
    await this.page.goto('/checkout');
  }
}
```

```ts
// e2e/i18n/critical-elements.visual.e2e.ts
import { expect, test } from './i18n.fixture';

test.describe('FEATURE: critical element snapshots', () => {
```

### Font Loading for i18n

CJK and Arabic fonts load late; a snapshot taken before they arrive shows the fallback font. `HomePage.waitForFonts` waits for `document.fonts.ready`, then for `document.fonts.check` to confirm the named family is usable.

```ts
// e2e/i18n/home-fonts.visual.e2e.ts
import { expect, test } from './i18n.fixture';

test.describe('FEATURE: home page snapshot with web fonts', () => {
  test('SCENARIO: the page matches its snapshot once Noto Sans Arabic has loaded', async ({ homePage, page }): Promise<void> => {
    await test.step('GIVEN the home page is open', (): Promise<void> => homePage.goto());

    await test.step('WHEN Noto Sans Arabic has loaded', (): Promise<void> => homePage.waitForFonts('Noto Sans Arabic'));

    await test.step('THEN the page matches with-fonts.png', (): Promise<void> => expect(page).toHaveScreenshot('with-fonts.png'));
  });
});
```

## Anti-Patterns to Avoid

| Anti-Pattern              | Problem                         | Solution                        |
| ------------------------- | ------------------------------- | ------------------------------- |
| Hardcoded text assertions | Breaks in other locales         | Use test IDs or parameterize    |
| Single locale testing     | Misses i18n bugs                | Test multiple locales           |
| Ignoring RTL              | Layout broken for RTL users     | Dedicated RTL project           |
| No font wait              | Screenshots with fallback fonts | Wait for `document.fonts.ready` |
